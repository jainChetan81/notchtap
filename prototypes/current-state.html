01 — General

Four groups: Engine (start-paused / hide-when-idle / record-history / now-playing toggles, listener port, a test-notification button), Rotation and priority (rotation seconds, queue cap per tier, manual push priority), Rotation order (a reorderable list — same-tier tie-break), and Silenced (a persisted daily buffer window, distinct from the tray's session-only Timed Mutes/Skip). Numbers below are this build's real config.rs defaults: rotation seconds 8, queue cap 50, listener port 9789.

Sections summarized (not laid out pixel-by-pixel)

Every other section, with its real control list and verified copy — same window chrome (sidebar/header/footer) as above, just not re-rendered control-by-control here.

  • 02 Football — one group ("Score polling"): a Football identity chip, ESPN-scores enable toggle, a leagues textarea (one ESPN league code per line, caption "one league code per line"), poll interval, rotation seconds, a "Live match card" toggle (consolidate updates into one card instead of a burst), a "Richer match events" toggle (fouls/offsides/VAR/subs — heavier polling, opt in per match), priority segmented, and a "Test football notification" button.
  • 03 News — RSS polling: enable toggle, feeds textarea, topics textarea (searched via Google News, merged into the same stream), poll interval, headline rotation seconds, max-per-poll burst cap, priority segmented, test button, an ad-hoc "Search now" row (one-off Google News search, not saved as a topic), and a read-only category-colour legend.
  • 04 Weather — keyless Open-Meteo polling. Identity chip, enable toggle, latitude/longitude (decimal degrees), a Celsius/Fahrenheit units segmented (display only — alert thresholds are always Celsius), poll interval, rain threshold %, rain lookahead minutes, hot/cold temperature thresholds (°C), priority segmented, test button.
  • 07 Shortcuts — one group, a real <table> (not a div grid, per the "shortcuts cheatsheet is a real table" test contract) of exactly 7 rows, every one currently "active": ⌃⇧N expand/collapse the slot manually, ⌃⇧O open the current story's link, ⌃⇧X dismiss the visible notification now, ⌃⇧P pause/resume promotion, ⌃⇧] skip to the next waiting item, ⌃⇧A open/focus the front Agent Session's host app, ⌃⇧, open settings.
  • 08 Appearance — two groups: "Card shape" (three bare, unlabelled Segmented controls — Scale: Small/Medium/Large [0.85/1.0/1.15], Radius: Square/Soft/Round [0/8/16px], Opacity: Glass/Default/Solid [0.7/0.9/1.0] — applied live to the real overlay via set_appearance, plus a "Live check" test button), and "Overlay animations" (a preview gallery that renders the real, imported StatusRailCard component across the fixtures in previewFixtures.ts, reflecting the shape settings above live — not re-implemented as a mock).
  • 09 Diagnostics — one group: a read-only <pre> tail of recent app log lines, fetched on section-open, plus a manual Refresh button (no live tail).
  • 10 History — a reverse-chronological list of recorded notifications (time, origin, title, metadata chips for source/category/priority/event-type/rotation, body, an expandable native <details> "More details" — its <summary> got today's press-feedback pass too, active:scale-[0.97]), fetched on section-open, plus a two-step-confirm Clear-history button.
  • 11 Queue — a plain list of items waiting behind the visible card (title + priority chip), a manual Refresh button, a Skip-current button, and a Clear-queue button.
  • 12 About — five groups: identity (brand mark, "Local-first notification HUD for your Mac.", live version + bundle id), "What it is" (one paragraph — cards slide out beside the clock, over the notch or as a floating top-center HUD, everything local via a Rust core on 127.0.0.1:9789), "How to use it" (four items with inline snippets: ./notchtap --title "t" --body "b" pushes a card, notchtap run -- <cmd> wraps a long-running command, connectors live in their own tabs, then the ⌃⇧N/⌃⇧O/⌃⇧, shortcuts), "Tech stack" (chips: Rust core, Tauri v2, React + TypeScript, Motion, Vite — "Built across 130+ small reviewed plans."), and "System" — a live, 2-second-polled 2×2... actually 2×3 stat grid (App memory, System memory, Disk, Platform · arch, Bundle size, Uptime), each tile entering with a Motion stagger on first mount only.
