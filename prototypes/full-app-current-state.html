Overlay

The rust-core-driven notch/HUD card — src/App.tsx crossfades between two top-level surfaces (a status-rail card and, when an agent needs the operator, the Agent Board) in one stacked grid cell so the swap never pushes the window taller mid-transition. Rendered here in HUD form (a notchless display draws its own synthetic black cutout) — notch-mode hardware is visually identical in shape, just with a real camera housing instead of the drawn rectangle.

1.1 Shell resting states

Origin-independent — bare/idle content never depends on which notification origin will eventually promote into it. [general] hide_when_idle chooses Idle rail (default) or Bare notch as the resting shape; a bare notch still reveals the full rail on hover (the tracking area keeps working even with zero pixels painted).

Bare / minimal paints zero pixels except the cutout itself — flanks fully transparent, shell width shrunk to exactly the cutout, HUD corners squared off to read as hardware. Bare, hovered reveals the full black rail (clock + status dots) without changing which notification is showing (there is none). Idle, face revealed is IdleFace: after ~4.5s of continuous true-idle a minimal two-eyes-and-a-smile face fades into the cutout's own grid cell and glances/blinks on a slow, capped-cost cadence — hidden instantly the moment a card shows or the cursor hovers.

1.3 Agent Board — post board-motion-polish

The hero for the primary session stays mounted in both resting and expanded states — hover only swaps what renders below it (the compact rows morph into the richer scrollable list, with per-row hover-disclosed transition history); a one-session board simply keeps its hero as-is on hover, never shrinking or swapping content out. The resting↔expanded swap is one continuous grid-stacked morph (both branches occupy the same cell, so the row height traces max(outgoing, incoming)) rather than a collapse-then-grow. Working-only sessions no longer auto-summon the Board — [agents] board_show_working defaults to false, so the Board stays out of the way until a session actually needs the operator (a permission/input request, a failure, or a just-finished turn); it still lists every retained working session once it's up for another reason. The hero plays its own identity-swap fade only when a different session becomes primary — an in-place state change (e.g. working → needs-approval) morphs the accent color instead of replaying the whole block.

About

What notchtap is, how to use it, and live process/system stats.

◆
notchtap

Local-first notification HUD for your Mac.

v0.7.0 · com.notchtap.app

What it is

Cards from your tools slide out beside the clock — over the notch on a MacBook, or as a floating top-center HUD on a notchless display. Everything runs locally: a small Rust core listens on 127.0.0.1:9789, and the window only renders what the core sends it.

How to use it

  • ./notchtap --title "t" --body "b" pushes a card.
  • notchtap run -- <cmd> wraps a long-running command and pushes a completion card when it finishes.
  • Connectors for football scores, personalized news topics, and weather are configured in their own tabs.
  • ⌃⇧N expands a card, ⌃⇧O opens its link, ⌃⇧, opens settings.
