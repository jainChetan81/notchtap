tab-notch proposal 2/2 — selected-tab cards

There is no panel. The neon icon-tabs sit on the notch's right flank (proposal 1/2 owns their design). Selecting one changes exactly one thing: which source's card the existing below-block shows when you hover the notch. That card is the card we already ship — same masthead kicker, same priority Stamp, same 3px accent stripe, same priority and runtime washes, same fact pills, same score block, same manifest. This page is a catalogue of those six selections in the compact form hover shows, plus the shortcut-expanded state prefix+enter opens.

Hover always shows COMPACT. There is no hover-expand anywhere in this proposal. Hovering the notch reveals the selected tab's card in its compact form and stops there. Expanded is a keyboard-only state reached with prefix+enter, and it closes the same way. The toggle under the rig is therefore labelled a shortcut-expanded preview — it is a way to look at that state on this page, not a pointer gesture the app has.

What was rejected. The earlier version of this file argued for a 500x360 tabbed dashboard with its own tab strip, grid and interior language. Operator decision: no big panel, no second design system, nothing new opens. That concept is gone from this file entirely — not softened, not parked. The below-block we already ship is the whole surface.

Hard rule, stated once. This file has no reduced-motion variant and no accessibility variant of anything. That is a permanent non-goal for this project, not an omission. Mac mini HUD mode only: a synthetic 200x32 cutout drawn by the app, never real notch hardware.

Where the visuals came from. Every class, colour, radius, inset and duration below was read off the live overlay source, not off an older prototype file: card-chrome.css, masthead-content.css, manifest.css, news-category.css, live-scorecard.css, agent-board.css, weather-art.css, idle-peek.css, ttl-bar.css, source-identity.css, NotificationBody.tsx, AgentBoard.tsx, presentation.ts. The Stamp words (Now, Done, Live, Wire) are the real lookup table, not invented labels.

the demo — one notch, six selections

Pick a tab. The strip on the notch's right flank lights the matching icon and the below-block swaps to that source's card. On the agent tab, prefix-[ / prefix-] walks the registered sessions and the bright segment on the card floor follows. Exactly one page is ever painted, every per-variant part obeys the variant, and the runtime wash is read back out of computed style — the self-check under the rig proves all three on every switch.

The floor strip, settled. A tab-summoned card was not promoted — nothing pushed it, you asked for it — so it never counts down. The 4px floor strip survives on pulled cards as a position indicator instead: ten segments for the ten stories in a news cycle, four for four registered agent sessions, bright for where you are. Pushed interrupt cards keep the real draining TTL and expire; pulled views persist. Same strip, and the presence or absence of the drain is the whole tell. Football's persistent variant carries no strip at all, which is already how it ships.

what each selection shows

1 — agentsshipped cardsession bar

  • The card is the shipped card. The hero runs through the unified template — AGENT kicker, real Stamp, prose title, runtime · project subtitle, body, fact pills with fp-tag qualifiers — sitting on the runtime identity wash and its hairline, with the 3px priority stripe flush to the card's own left edge.
  • The wash is the point. agent-origin puts a static corner radial in ::before (120% 140% at 0% 0%, --cat-deep, out by 52%) and a --cat-keyed hairline on the top border; .compact rides above it at z-index 1. Cycling the hero rewrites the src-* class, so the card warms to terracotta for Claude Code, green for Codex, purple for OpenCode. If it ever reads as flat black, that stack is broken — and the self-check under the rig now prints the exact colour it resolved to rather than leaving it to the eye.
  • The session bar is new. One segment per registered session on the card floor: the shipped ttl-bar's exact geometry (4px, 3px gaps, one grid column each) with the drain removed. Bright --accent is the session you are viewing, the 30% trough is the rest. It reads from the priority channel, never the origin channel, because a floor bar is card chrome like the Stamp and the priority edge — the hero above it can be painted by origin, the bar under it cannot.
  • Pulled views persist; pushed cards expire. This card has no countdown because nothing pushed it — you asked for it, so it stays until you go elsewhere. A PUSHED agent interrupt (a completion, a permission prompt) is unchanged: it arrives on its own, carries the real draining TTL bar, and times out. Same 4px strip, two different jobs, and the presence or absence of the drain is what tells them apart.
  • All four sessions stay visible — as segments in compact, and as the shipped one-line roster rows (dot, runtime tick, runtime, project, state, elapsed; never a "+N" collapse) once prefix+enter opens the expanded state. The viewed row is lifted so the roster and the bar agree.
  • The dot's pulse stays bounded (one tick, four breathes, then rest). An always-on pulse was deliberately removed from this app; a tab that summons the board must not smuggle it back.
  • Flagged, not answered. The generic Stamp table has three words (Live / Done / Now) and none of them means "stale". This file uses Done for the stale session rather than inventing a fourth.

2 — footballshipped card

  • Compact is the shipped scorecard: football kicker and dot, the real per-signal Stamp (Live / Card / Final…), the event line as the headline, and the score-block hanging off its own 10px margin-top — sc-head chips, score-row with crests and odometer digits, cards-line.
  • Permanent while live. Shortcut-expanded (prefix+enter) is the crossbar-style persistent variant: two stacked score-blocks, no event headline, no TTL bar. While a match is live and the football tab is selected, this does not time out and never needs re-summoning — it is a standing readout you glance at, the same way the shipped sticky live card already behaves.
  • A goal still interrupts. Selection decides what rests under the notch, never what a goal is allowed to do.

3 — music / medianew controls

  • Now-playing poured into the shipped skeleton: media kicker, track title as .title.headline, artist as the subtitle row, then the album tile, transport and thin .media-bar in the body area — the same bar the idle peek already draws, still scaled with a transform rather than a width.
  • The controls are the new MediaRemote command surface. Everything else on this page is existing vocabulary; prev / play-pause / next are new because the vendored MediaRemote adapter gives us commands, not just a read-only string. They are drawn in the existing chip and tile language — same tints, same radii, same press-scale — so a new capability does not arrive as a new look.
  • Shortcut-expanded (prefix+enter) adds the scrubber (drag to seek) and a three-row queue preview. Nothing here has a TTL: media is a live surface, not an event.

4 — weathershipped card, tightened

  • Essentially unchanged, re-derived strictly. Every value here comes off weather-art.css and idle-peek.css at its shipped size: the .wx-card mood gradient at z-index 0, the 28px condition glyph, the 18px mono-800 temp, the neutral .wx-peek-condition chip, .wx-peek-hilo with its leading middot, and .wx-peek-rain in the same light blue the rain-streak texture already uses.
  • What r2 had invented, and is now gone: a 30px "big" temp variant (shipped is 18px, full stop), a column-stacked .wx-forecast-point (shipped is a row), an unpadded forecast strip (shipped is padding: 0 12px), and a made-up .wx-forecast-glyph class name (shipped is .wx-forecast-icon). The readout is also a sibling of .compact rather than a child, because it brings its own 10px/12px padding and nesting stacked the two.
  • The readout and strip share one .wx-peek-weather-stack so .peek-content's 8px gap applies exactly once, whether or not the strip is mounted — the shipped reason that wrapper exists.
  • Rain conditions bring the shipped rain-streak texture with its seamless 23.66px loop. prefix+enter opens the manifest block, the same disclosure the news card uses on the same 320ms grid-rows transition.
  • A severe-weather alert still interrupts as a high-priority card, selection or no selection.

5 — newsbatch header

  • The shipped news card: source masthead with its category dot, the real Wire stamp, the headline, the category chip and the relative age, all over the drifting category shade. prefix+enter opens the summary manifest exactly as shipped.
  • The batch header is new — "10 fresh · cycle ended 2m ago", ten dots, prev / next. It exists because a tab-summoned card is not a promotion: nothing pushed it, so it has to say how big the pile is and let you walk it. Held to one mono line in the masthead's own type so it reads as card chrome, not a toolbar.
  • Opened via the charged icon, never interrupts. A finished news cycle charges the news icon on the flank; it does not promote a card at you. Breaking-news interruption is explicitly a future thing, out of scope here.

6 — none selected

  • The bare hover face: painted flanks, the clock, the icon strip, nothing underneath. With no below-block in the DOM the rounding law hands the outer corners back to the flanks and the cutout, so the shape reads as a notch again rather than a card — that handoff is the shipped rule, not a special case built for this page.
  • This is the honest default. If you have selected nothing, the notch owes you nothing.

On every page, without exception. High-priority interrupting cards — a goal, an agent completion, an agent waiting on permission, a severe weather alert — still arrive exactly as they do today, regardless of which tab is selected or whether any tab is. Tab selection decides what the notch shows when you go looking. It never decides what the notch is allowed to tell you.
