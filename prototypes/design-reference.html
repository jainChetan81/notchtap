Easing curves

Three curves cover the whole app. --ease-notchtap is the house settle; the pop curve is scoped to one thing only (a genuine new-notification width grow); the interrupt curve is a sharp ease-in used exactly once, for a priority-preemption yank.

--ease-notchtap

cubic-bezier(0.22, 1, 0.36, 1) — the default everywhere: reveal/expand/exit widths, hover breathe, flank corners, gill opacity, content fades.

--ease-notchtap-pop

cubic-bezier(0.3, 1.36, 0.44, 1) — a slight overshoot. Scoped ONLY to the base .card-assembly width leg (a real promotion), never the hover-reveal or expand-toggle legs (plans 164/165 pulled those back to the plain curve).

--ease-interrupt

cubic-bezier(0.4, 0, 1, 1) — a sharp ease-in, used once: the content-exit "yank" when a strictly-higher-priority event preempts what's showing.

Scope & source

  • Settings nav icons are two-letter mono badges, not the real Lucide icon set — structure and press/active-state behavior are accurate, glyphs are not.
  • Only the Agents and Appearance settings sections are rebuilt from real component copy; the other ten sections show a placeholder noting they share the same control library.
  • The real Rust-derived hover tracking area is stood in for by manual toggles/buttons (overlay hover) — the Agent Board's per-row history disclosure genuinely uses native hover here, matching the real feature's own real-pointer-events behavior while expanded.
  • ROW_TRANSITION and DISCLOSURE_SPRING are Motion springs; this file approximates them with cubic-bezier/CSS transitions since it has no physics solver.
