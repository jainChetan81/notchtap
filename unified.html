1. How to use — 30 seconds

Install
npm ci + Rust via rustup + cargo build from src-tauri/. First time: just setup, just build-media-adapter (MediaRemote, no sudo), brew install just if you don't have it.
Run (dev)
npm run tauri dev — overlay HUD appears top-center (HUD on Mini, notch-anchored on MacBook). No dock icon — lives in the menu bar. Tray icon is the only chrome.
Push a card
./notchtap --title "hello" --body "world" → 127.0.0.1:9789/notify (override --port / $NOTCHTAP_PORT). Or notchtap run -- pnpm build — wraps a long command, pushes a completion card (skipped if fast success > --min-secs 15, always on failure).
Settings
Tray → Settings… → 12 sections (General, Agents, Football, News, Weather, Connectors, Keys …). Saving always relaunches the app — there is no hot-reload. Every keybinding and priority lives here.
Where it lives
Built app + config + logs under ~/Library/Application Support/notchtap/. History is SQLite inside the engine. src/ is authoritative; prototype/*.html is the static mirror.
Two machines, one build: the same binary runs on the notch MacBook and the notchless Mini. At launch notchtap-detect (Swift) prints safeAreaInsets.top; >0 → Notch, else → HUD. On HUD a synthetic 200×32 cutout is drawn so the card geometry stays mode-agnostic.

Live console — control the running app

127.0.0.1:9789file:// + fetch

This panel actually POSTs to your local engine when it’s running (npm run tauri dev). No build step, no CORS trick — Tauri’s loopback allows file:// → 127.0.0.1 fetch. If the engine is off, you’ll get “connection refused” — that’s expected.


      
Shortcuts still work when this file isn’t focused — they’re global. This console is just a second way to fire the same POST /notify {title, body, priority} that ./notchtap uses. Try High while Silenced to see Breakthrough; try ⌃⇧P then push to see 202 buffering.

Why the workflow and animation feel shit today — teardown

  
This is the section your note asked for directly. No hedging: the Slot engine is great, the surface that shows it isn’t. Three layers cause it — scheduled motion, undiscoverable workflow, and static mirrors.

  

    
Motion — scheduled vs pursuit
Worst gap

      
What we do: every transition is a cubic-bezier(.22,1,.36,1) with a baked duration (175/105/320/260). Correct tokens, but time-driven — the card moves the same whether you hovered gently or slammed the cursor.

      
What they do: Notchy’s changelog 1.0.86 “one shared spring language”, 1.0.70 “120fps lag-free opening … faster spring curves”, 1.0.73 “glitch-free collapse”. Crossbar’s .reel { translateY } is a follow, not a fade. Motion follows velocity, not a timer — so it feels alive.

      
Why it reads as “shit”: our BOARD_SURFACE_MOTION is opacity-only (deliberate — scaling the synthetic notch “looks weird”, App.tsx comment). Correct not to scale the cutout, but we also didn’t add the replacement language (spring on the below-block, micro-follow on hover). So the card is correct and lifeless. Notion: correct ≠ alive.

      
Fix: keep tokens as the at-rest law; add a velocity-aware spring layer on hover/reveal/expand (spring stiffness 380 / damping 26 starting point, whileHover micro-translate, haptics(4) tap). One file, additive — no token rename.

    

    
Workflow — powerful and invisible
Discovery

      
What we do: 7 globals + prefix → 2s window → 1-5 / [/] / enter / p / esc — all rebindable in Settings → Keys. Powerful. Requires reading a table to find.

      
What they do: Notchy: ⌃⌥K command palette + Knock double-tap modifier → notch opens; Boring: two-finger swipe; Crossbar: 3 always-visible pills (⌘⌥/ hide). Every app has a single gesture that teaches itself.

      
Why it reads as “shit”: our overlay is receive-only by design (capabilities/default.json — overlay never invokes). Good security, but the only discovery surface is Settings, which is a second window that relaunches the app on save. No palette, no tip island, no hover affordance that lists what you can do before you do it.

      
Fix: palette over prefix (same keys, just a surface) + one Knock-style tip (“double-tap ⌃⇧ to see what the notch can do”). Not new bindings — surfacing what exists. See fixes 6 & 7 below.

    

    
Prototypes — accurate and flat
Docs

      
What we do: prototype/*.html — 8 standalone mirrors, hand-authored, header says exact source + sync date (2026-07-30/08-02). src/ is authoritative; prototypes are honest mirrors.

      
What they do: Crossbar ships one looping notch demo on the landing page; Boring ships a GIF; Notchy ships 10 looping mp4s (pillshape/music/lyrics/clipboard/pomodoro…). Each is 17–36s, silent, looping, gesture-visible.

      
Why it reads as “shit”: our mirrors are pixel-accurate and motionless. A reviewer compares a static notch-states.html iframe to a Notchy mp4 where the pill springs open, follows the cursor, and ticks a pomodoro. Even if our motion were fixed, a static mirror can’t show it.

      
Fix: one demo/*.mp4 per origin (17–30s, silent, looping) recorded from the shipped overlay — same role as their demos but from our own build. Half-day, biggest perception lift per hour.

    

    
The through-line
Diagnosis

      
Each gap alone is modest. Together they make the product feel “more feature, less love”: the Slot/priority/rotation engine is the most disciplined notch queue of any app in this comparison (nobody else has per-tier caps + preemption with remaining-time + Silenced/Breakthrough), but the shell that presents it moves on a timetable instead of following your hand, hides its power behind a settings window that restarts the app, and documents itself with still images. The engine is A-tier; the surface is B-minus. Fixes 1–8 close that split without touching the engine.

    

  


  

    Distribution bottleneck — still the #1 ship blocker (notchtap, not the competitors): none of them is App-Store-strong either — Boring needs the same quarantine toggle, Crossbar ships a raw DMG, Notchy ships a raw DMG — but they ship while notchtap today only cargo builds. Zero signed bundles. Whoever adds sign + notarize + auto-update (latest.json + minisign) first turns a parity into a lead. Spike exists (plan for Tavily-style update machinery) — wire it before any more card polish.

The eight fixes — what to steal, what to build

  

    
1. Reel tiles — from Crossbar
Motion
Problem: score changes by replacing a digit. Eyes miss it.
Steal: Crossbar’s .reelWindow → .reel { translateY } — the old number scrolls out, the new scrolls in. Goal is then a before/after, not a jump. Scope: TtlBar.tsx/score path only; one new component, no engine change.

    
2. Celebration as narrative — from Crossbar
Card
Problem: our celebration is confetti + pulse — pretty, but anonymous (what just happened?).
Steal: Crossbar’s two-act (heroBall → GOAL → reveal[flag+scorer+minute]). Ours can be badge-wave → SCORE → team + scorer + minute inside the same shell height — no replay video needed v1.

    
3. Visualizer bottom-third — from Boring
Music
Problem: MediaBelowBlock is a text card on a notch — wasted theatre.
Steal: Boring’s waveform strip (thin, low-opacity, audio-reactive bar). Not playable artwork re-colour — a real amplitude ribbon under the track line. Block stays compact; theatre lives in 10 px.

    
4. Resizable expanded panel — from Notchy
Chrome
Problem: expanded width is fixed; large artifacts feel cramped, small ones feel baggy.
Steal: Notchy’s drag-resize. Even 3 presets (compact / medium / large) with a remembered preference would close 80% of the gap. Wire to --card-radius/--card-scale discipline we already have.

    
5. Spring + follow + haptics — from Notchy
Motion (biggest gap)
Problem: tokens are correct but scheduled (175/105/320 keyframed). Competitors feel pursuit-driven — the surface follows the pointer/gesture, not a timer.
Steal: Keep every token as the at-rest value; add spring on hover/reveal (motion spring: { stiffness: 380, damping: 26 } is the starting guess) and whileHover micro-follow + haptics(4) on expand. No token needs renaming — just a second path that’s velocity-aware.

    
6. Command palette + Knock — from Notchy
Discovery
Problem: six globals + prefix is powerful and entirely undiscoverable. New users read nothing.
Steal: Notchy’s ⌃⌥K palette + “Knock” double-tap. Our palette is one command set away (the prefix keys are the palette). Double-tap ⌃⇧ could arm prefix visually — no new bindings, just a surface that lists what you already have.

    
7. Loopable demos, not static mirrors — from all three
Docs
Problem: prototype/*.html are still images — no gesture, no momentum, no loop. Competitors demo with 17s silent mp4s.
Build: one demo/*.mp4 per origin (17–30 s, silent, looping) recorded from the shipped overlay — same role as Boring/Notchy’s demos but from our own build. Embed in README + Settings Help. This is a half-day that changes the first impression more than any code fix.

    
8. Sign + notarize + auto-update — gap vs everyone
Ship
Problem: nobody is App-Store-strong — but everyone else ships a DMG. Notchtap builds but does not distribute.
Build: finish the Tavily-planned update path (latest.json + minisign — pattern from Notchy/Boring bundle + Handy’s latest.json convention). A signed, auto-updating nightly beats a perfect card that nobody installs. Do this before fixes 1–7 or 1–7 won’t get seen.
