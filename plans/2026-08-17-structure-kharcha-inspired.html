Structure — notchtap, Kharcha-inspired

How Kharcha organizes lib, hooks, components and what notchtap should steal — recorded 2026-08-17, branch chore/anti-slop-cleanup

TL;DR
  • Kharcha's strength: one lib/ for pure helpers, one hooks/ for data, one components/ui/ for primitives, no utils junk drawer. Constants, format, validation, and date helpers each own a file. Screens never call query directly.
  • Notchtap today: src/lib/ already has guards and error, but constants are scattered in animationTiming.ts, formatting is split between byteFormat.ts and timeFormat.ts inside settings/, and 7 hooks live at src/*.ts root. No central lib/constants.ts, no lib/format.ts, no src/hooks/.
  • This pass creates src/lib/constants.ts, src/lib/format.ts, src/lib/validation.ts, and src/hooks/, moves the 7 hooks there with re-exports for compat, and deletes the two settings/ format files after re-exporting. No behavior change, all imports stay green.

3 · Rules stolen from Kharcha

  • One file, one domain. constants.ts holds constants, format.ts holds formatters, validation.ts holds validators. No utils.ts junk drawer.
  • Named exports only. Every helper is a named export. No default exports, no barrel index.ts that re-exports everything.
  • Hooks own data. Screens call hooks, hooks call Tauri events. No screen reaches directly into window.__NOTCHTAP_* or listen().
  • Re-export, don't duplicate. When moving byteFormat.ts → lib/format.ts, the old path re-exports until all importers are migrated, then is deleted. Same for hooks at root.
  • Colocate CSS with its component. src/overlay/*.css stays next to the overlay components, like Kharcha's components/ui/*.tsx keeps its own styling.

4 · Implementation — 4 small commits

  1. Create src/lib/constants.ts — move animation timing constants (HOVER_MS, REVEAL_MS, BOARD_SUMMON_MS, SURFACE_SWAP_MS, NOTCHTAP_EASE) and default port/limits from animationTiming.ts and types.ts. Keep animationTiming.ts as a thin re-export for compat until callers migrate.
  2. Create src/lib/format.ts — re-export formatBytes, formatBytePair, formatUptime, formatClockTime, formatRecordedAt. Update importers, delete settings/byteFormat.ts and settings/timeFormat.ts.
  3. Create src/lib/validation.ts — thin wrapper that re-exports isValidAgentState, isValidSlotState, isValidStatusState for future shared use. No validator logic moves yet; this is the seam for the next pass.
  4. Create src/hooks/ and move 7 hooks — useAgentState, useSlotState, useStatusState, useTabSelection, useAgentViewedSession, useDelayedSwap, useClock, useExitChoreography. Update imports in App.tsx, SettingsApp.tsx, tests, and keep a one-line re-export at the old src/use*.ts path until the move is complete, then delete.

Each commit must keep npx tsc --noEmit, npx oxlint 0, and npx vitest run 748 green. Verify with just test-all (cargo test 953).
