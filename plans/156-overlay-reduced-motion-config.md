## Problem

The overlay window (the app's primary, highest-frequency surface — every
notification renders through it) has **zero** JS-level `prefers-reduced-motion`
handling. The settings window does this correctly; the overlay entry point
does not.

`src/settings/SettingsApp.tsx:361` (current, correct — for reference only,
do not edit this file):

```tsx
return (
  <MotionConfig reducedMotion="user" transition={{ duration: 0.16, ease: NOTCHTAP_EASE }}>
    <main ...>
```

`src/main.tsx` (current, the file to fix — full contents):

```tsx
import React from "react";
import ReactDOM from "react-dom/client";
import App from "./App";
import { applyAnimationTiming } from "./applyAnimationTiming";
import "@chetanjain/shared-ui/design/tokens.css";
import "./overlay-card.css";
import "./styles.css";

applyAnimationTiming();

ReactDOM.createRoot(document.getElementById("root") as HTMLElement).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>,
);
```

`<App />` is mounted bare, with no `MotionConfig` ancestor. A repo-wide
check confirms only one of the overlay's eleven `motion/react` consumers
(`src/components/TtlBar.tsx`) reads reduced-motion state at all (via the
separate `src/prefersReducedMotion.ts` hook, which is JS-and-CSS-only, not a
`motion` primitive). Every `motion.div`/`AnimatePresence` transform
animation in `src/App.tsx`, `src/components/StatusRailCard.tsx`,
`src/components/AgentBoard.tsx`, `src/components/IdleHoverPeek.tsx`,
`src/components/IdleFace.tsx`, and `src/components/LiveMatchScorecard.tsx`
currently has no reduced-motion opt-out whatsoever.

## Target

`src/main.tsx` wraps `<App />` in a `MotionConfig` with
`reducedMotion="user"`, matching the settings window's own pattern exactly
(same prop, same value — do not invent a new configuration):

```tsx
import React from "react";
import ReactDOM from "react-dom/client";
import { MotionConfig } from "motion/react";
import App from "./App";
import { applyAnimationTiming } from "./applyAnimationTiming";
import "@chetanjain/shared-ui/design/tokens.css";
import "./overlay-card.css";
import "./styles.css";

applyAnimationTiming();

ReactDOM.createRoot(document.getElementById("root") as HTMLElement).render(
  <React.StrictMode>
    <MotionConfig reducedMotion="user">
      <App />
    </MotionConfig>
  </React.StrictMode>,
);
```

Note: unlike `SettingsApp.tsx`, do **not** also pass a shared `transition`
prop here — the overlay's various `motion` consumers each already specify
their own explicit per-animation `transition` (see `StatusRailCard.tsx`,
`AgentBoard.tsx`, etc., all of which set `transition={{ duration: ..., ease:
NOTCHTAP_EASE }}` per call site). `MotionConfig`'s `reducedMotion="user"`
prop alone is sufficient to make every descendant `motion.div` automatically
disable transform-based animation (translate/scale/rotate) under
`prefers-reduced-motion: reduce`, while leaving `opacity` animations intact
— this is Motion's built-in behavior for `reducedMotion="user"`, not
something this plan needs to implement per-component.
