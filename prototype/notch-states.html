notch states — mirrors the shipped overlay

Same permanent notch cutout, same pure-black shell, in both notch mode (a real MacBook notch, hardware-measured width) and HUD mode (a notchless Mac, where the app draws its own .synthetic-cutout rectangle at a 200×32px stand-in size) — one runtime shape, no build-time fork (docs/ARCHITECTURE.md §8). The rigs below are a static hand-authored approximation of that shape and its states, not a compiled build of the real component tree.

This file used to carry a "historical prototype, deliberately diverged" banner. That framing is retired: this version was written by reading src/App.tsx, StatusRailCard.tsx, useExitChoreography.ts, IdleHoverPeek.tsx, and the src/overlay/*.css stylesheets directly, and pulls its widths/colors/timings from those files. It is still a static mock (no React, no motion, no build step) and will drift the next time those files change without a matching pass here — verify against source before treating a specific pixel value as current truth.

Zero app-drawn pixels until hovered: transparent flanks, cutout-width- only shell, so there's nothing painted over the desktop but the notch itself. 3 — the general notification card lifecycle

One card, three geometry states (compact → expanded → exiting), driven by <StatusRailCard> + useExitChoreography. Push a notification, toggle the expanded manifest with the same hotkey the real app uses (⌃⇧N), watch the TTL bar drain (hover the card to pause it — hoverPaused), and see it exit back to whichever resting state you've picked. "Interrupt" models a Priority Preemption: a strictly-higher-priority arrival cuts the current card off with a fast, sharp "yank" exit (INTERRUPT_EXIT_MS 60ms, INTERRUPT_EASE) and immediately promotes, rather than fading gently like an ordinary close. The real queue can hold more than one Waiting item at once; this demo only ever models the single Visible slot.

5 — resting-state option: rail vs. bare notch

A config choice (appearance-changed's resting_state field), not a second design: promotions, expansion, hover peeks, and exits all behave identically either way — only what's painted when truly idle changes. "rail" (default) shows the time+dots pill from section 2; "notch" shows nothing beyond the bare cutout from section 1 until hovered. Exiting INTO bare mode is a single converged shrink (shell width, flank paint/padding, and the synthetic-cutout's corner radii all animate to the bare target over the same --swap-exit-ms window, .exiting.exit-to-bare) rather than shrinking to rail width first and then popping to bare — that two-step version was a real, since-fixed bug (see card-chrome.css's own comment on that selector).
