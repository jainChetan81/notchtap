agent board — mirrors the shipped Agent Board

App.tsx swaps this in as a whole separate top-level surface — never a StatusRailCard variant — whenever the independently- updating agent-state channel currently holds at least one gated-in session and the engine isn't Paused (pausing quiets the whole notch, Board included). Same notch/HUD shell as every other card (flanks, cutout, below-block, drop-shadow), but its own dedicated below-block content: one rich "hero" for the top-ranked session — now rendered through the SAME masthead/stamp/title/subtitle/body/fact-pill template every other card uses, not a bespoke block — plus every other session as a single compact line, never a "+N" collapse (spec's own explicit rule), and, on hover, a bounded scrollable list with per-session detail and a per-row transition history.

This file is the missing sibling of notch-states.html, which explicitly scopes the Agent Board out of its own coverage. Built by reading AgentBoard.tsx, App.tsx, NotificationBody.tsx, agent-board.css, and the rust-side agents/board.rs/agents/model.rs directly — static mock, no React, no motion, will drift the next time those files change without a matching pass here.

1 — presence: which sessions earn the Board at all

Operator decision 2026-08-02: the Board's job is attention, not a dashboard. A session in a merely-Working, Starting, or Stale state does not, on its own, summon the Board — AgentSessionState::summons_board (rust, agents/model.rs) is true only for waiting_for_permission/waiting_for_input/ failed/a still-retained completed. This gate is evaluated in exactly one place — AgentBoardPublisher::gate_presence (agents/board.rs), before the wire snapshot is even built — so a gated-off board publishes as ZERO sessions and every downstream consumer (the overlay's presentationMode, the hover-expand primitive) stays ignorant of the knob entirely. The Settings toggle is [agents] board_show_working, default OFF — a deliberate behavior change from the pre- 2026-08-02 always-on Board.

This gates PRESENCE only, never CONTENT: once something has summoned the Board, it lists every retained session, working ones included — the row list below never filters. And it's a distinct knob from completion_notifications (also on/off in the same Settings section): that one gates whether a terminal session end pushes a promoted notification CARD; board_show_working gates whether the Board surface itself appears for working-only sessions. A session that already summoned the Board for another reason still lists its working siblings regardless of either toggle.

Ordering follows the same principle: urgency_rank guarantees every summoning state outranks every non-summoning state, so the session that actually summoned the Board always leads the hero — a Completed session that just summoned the Board can never lose the hero card to a merely-Working sibling (that was a real, fixed bug: the Board used to arrive announcing "Agent working" on exactly that scenario).

2 — resting, single session · all seven states

AGENT_STATE_PRESENTATION (lib/presentation.ts) — the closed lookup table every state's dot/accent resolves through — paired with AGENT_HERO_TITLE (per-state hero prose) and AGENT_STATE_PRIORITY (which of the shared low/medium/high accent tiers the state's card renders through). Five visual accent classes cover seven wire states: starting reads as a working variant (no separate visual language for a session's first few hundred ms). Note the Stamp badge (Live/Done/Now) comes from the SAME generic-priority table every non-football card uses — it isn't agent-specific, so "Done" while working and "Live" while completed look odd read literally; that's the shared vocabulary, not a mislabel in this mock.

5 — the Board's own summon & dismissal

One level up from this component: App.tsx stacks the Board and the ordinary status rail in a single grid cell (surface-stack) so their crossfade never pushes layout — the SAME technique the Board's own resting↔expanded swap uses one level down (section 6). Since the Board now only appears when an agent actually needs the operator, its ARRIVAL earns its own longer clock — BOARD_SUMMON_MS (260ms) against the routine rail↔rail crossfade's 180ms — while its EXIT stays on the shared, quieter SURFACE_SWAP_MS (180ms): an interruption should announce itself and then leave without ceremony. Both legs are opacity-only — a scale/drop entrance was tried and rejected on sight (2026-08-02, live operator feedback: "looks weird, something about its size animation"), because the wrapping motion.div also contains the synthetic notch cutout, and that cutout's whole illusion depends on being a fixed physical anchor. The standing law: any future entrance emphasis on this surface animates ONLY content below the cutout, never the shell.

6 — resting ↔ hover-expanded · one continuous morph

2026-08-02 operator feedback: "the compact<->expanded transition reads badly." It used to run mode="wait" — the resting rows collapsed ALL THE WAY to nothing before the expanded list was allowed to start growing, so a hover played as two chained beats with a full pinch-to-zero between them. Fixed by stacking both branches in ONE grid cell (.agent-board-swap) with BOTH kept on the same height spring, started the same frame — since a grid row sizes to the MAX of its items rather than their sum, the wrapper's height traces max(outgoing, incoming) as one continuous curve. The hero above is unaffected either way — it stays mounted in BOTH states (a fix for a separate bug: hovering a one-session Board used to swap its hero for a single skinny row, which read as the card getting SMALLER on hover — a hover must never shrink or swap the hero). The expanded list below only ever holds the OTHER sessions (rest), so each session appears exactly once at every session count.

Two clocks are deliberately asymmetric with their own "mirror the exit" sibling: the Board's summon (260ms in / 180ms out) and the per-row history disclosure vs. its own collapse both earn a different arrival weight than their departure, per this repo's house rule that an arrival can earn emphasis while a departure should stay quiet. Every OTHER transition in this file (rows, resting↔expanded) genuinely does mirror its own exit path — the asymmetry is scoped narrowly, not a general pattern.
