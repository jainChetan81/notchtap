agent board — mirrors the shipped Agent Board

App.tsx swaps this in as a whole separate top-level mode — never a StatusRailCard variant — the moment at least one agent session exists. Same notch/HUD shell as every other card (flanks, cutout, below-block, drop-shadow), but its own dedicated below-block content: one rich "hero" card for the top-ranked session, every other session as a single compact line, never a "+N" collapse (spec §6.2's own explicit rule) — and, on hover, a bounded scrollable list with per-session detail and a per-row transition history.

This file is the missing sibling of notch-states.html, which explicitly scopes the Agent Board out of its own coverage. Built by reading AgentBoard.tsx, agent-board.css, source-identity.css, and lib/presentation.ts directly — static mock, no React, no motion, will drift the next time those files change without a matching pass here.

⚠ proposal — the same states, through the unified shell

NOT current reality — see prototype/proposal-unified-card.html for the full cross-origin version of this idea. Above is AgentBoard.tsx's own layout, what's actually shipped. Here, the PRIMARY session renders through the generic NotificationBody.tsx template instead (masthead + stamp + accent stripe + title/body/details) — the same template manual/CLI, weather, and news already use today. The multi-session aggregate view doesn't fit inside a single generic card, so it becomes an ADDITIVE flavor instead: a restrained list of other sessions appended below, in the same mono/dot visual language the ttl-bar/queue system already uses elsewhere — not a replacement layout, an addition.
