Football card — shipped overlay mirror

This mock mirrors the football/live-match card as it actually renders today. There are two distinct real render paths, not one: the resting hover-reveal peek (IdleHoverPeek.tsx, label + minute only) while nothing newsworthy is happening, and the full event-driven scorecard (LiveMatchScorecard.tsx, crests + score + event line) that appears when a goal, card, or other event promotes the card to "showing." Goal / penalty / yellow / red celebrate the whole card shell; foul / offside / VAR / substitution open the same scorecard quietly, no celebration.

Class names, colors, and structure below are copied from src/overlay/card-chrome.css, src/overlay/live-scorecard.css, and src/overlay/idle-peek.css — every selector here is .card-root-scoped, matching the shipped stylesheet, so this file stays diffable against the real one by eye.

Match-state chip variants

The chip-live pill's three real variants — Live (default), Break (halftime), Final (fulltime). There is no "Soon"/pre-match variant: kickoff transitions straight to Live on the wire, so there's nothing to render beforehand.

Interaction demo — hover the rail, then fire an event

Hover the card. Resting shows the idle rail; hovering opens the compact peek. Firing an event closes the peek and swaps in the full scorecard with its celebration (or, for the quiet four, no celebration at all), then settles back to the idle rail after a few seconds.

Not wired into the build — a hand-maintained reference, so it can drift if those files change without this one being updated alongside them.
  • Corrected from the previous version of this file: the resting hover state does NOT show crests or a score — the ambient status.football.live summary the rust core polls only carries a label string and a minute string (useStatusState.ts's LiveMatchSummary), so IdleHoverPeek.tsx can't render more than that.
  • Corrected: there is no .side-name team-name label under a crest anywhere in the shipped scorecard — only the crest itself (image, or the text-abbrev fallback shown throughout this mock, matching what renders when no cached crest image exists).
  • Corrected: the clock-pill span carries both chip and clock-pill classes in the real component, not clock-pill alone.
  • Corrected: there is no pre-match "Soon" state — removed rather than kept as a labeled proposal, since no wire signal exists for it today.
  • Simplified: score digits render at rest here; the real component rolls each digit through a small vertical clip on change (ScoreDigit in LiveMatchScorecard.tsx, via motion/react) — the DOM shape (.score-digit/.score-digit-roll) is reproduced, the roll animation is not.
  • Simplified: the hover "breathe" here uses real CSS :hover; the shipped card drives it off a rust-derived tracking-area signal instead, since the real overlay window is click-through and never receives pointer events.
