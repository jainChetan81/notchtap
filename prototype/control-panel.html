Control panel — the settings window (12 sections)

SettingsApp.tsx's navigation array is the source of truth for order/count: General, Football, News, Weather, Connectors & Keys, Agents, Shortcuts, Appearance, Diagnostics, History, Queue, About — 12 sections, sidebar icon + label each, no per-row index badge (the "01"/"02"… index now only appears in the pane header, e.g. "Settings / 06"). Three sections are drawn out in full below (General, Agents, Connectors & Keys); the other nine are summarized in prose with their real control list.

Tokens mirror vendor/shared-ui/design/tokens.css + src/settings/base.css: window #050607, sidebar #090a0c, surface/card #0d0f12, border/divider #202329 (also the value --input/ --accent/--secondary/--muted all share), accent/primary #0a84ff — used for the Save button fill, a checked Switch, focus rings, and the active sidebar item's tint/rail, not just one place. The type floor is four fixed sizes (9/10/11/19px, --fs-caption/secondary/body/title); nothing in this window uses a font size outside that scale except a couple of named, commented exceptions in the real CSS (e.g. the Appearance preview label's 12px).

01 — General

Four groups: Engine (start-paused/hide-when-idle/history/now-playing toggles, listener port, a test-notification button), Rotation and priority (rotation seconds, queue cap per tier, manual push priority), Rotation order (a reorderable list — same-tier tie-break), and Silenced (a persisted daily buffer window, distinct from the tray's session-only Timed Mutes/Skip).

06 — Agents

Sections not drawn out in full

Every other section, with its real control list and copy — same window chrome (sidebar/header/footer) as above, just not re-rendered pixel-by-pixel here.

  • 02 Football — one group ("Score polling"): a Football identity chip, enable toggle, a leagues textarea (one ESPN league code per line), poll interval, rotation seconds, a "Live match card" toggle (consolidate updates into one card instead of a burst), a "Richer match events" toggle (fouls/offsides/VAR/subs, opt-in — heavier polling), priority segmented, test button.
  • 03 News — one group ("RSS polling"): enable toggle, feeds textarea, topics textarea (searched via Google News, merged into the same stream), poll interval, headline rotation seconds, max-per-poll burst cap, priority segmented, test button, an ad-hoc "Search now" row (one-off Google News search, not saved as a topic), and a read-only category-colour legend (six chips: Politics/Tech/Sports/Business/World/Science).
  • 04 Weather — one group: keyless Open-Meteo polling. Identity chip, enable toggle, latitude/longitude (decimal degrees), a Celsius/Fahrenheit units segmented (display only — alert thresholds are always Celsius), poll interval, rain threshold %, rain lookahead minutes, hot/cold temperature thresholds (°C), priority segmented, test button.
  • 07 Shortcuts — one group, a real <table> (not a div grid) of 7 rows: expand/collapse (⌃⇧N), open story link (⌃⇧O), dismiss now (⌃⇧X), pause/resume (⌃⇧P), skip to next (⌃⇧]), focus front Agent Session's host app (⌃⇧A), open settings (⌃⇧,) — every row currently "active" (no planned-but-unshipped rows today).
  • 08 Appearance — two groups: "Card shape" (Scale/Radius/Opacity — three bare, unlabelled segmented controls each with 3 options, e.g. Small/Medium/Large — applies live to the real overlay via set_appearance — plus a "Live check" test button), and "Overlay animations" — a preview gallery that renders the actual StatusRailCard component (imported from the overlay, not re-implemented) across several fixture states, reflecting the shape settings above live.
  • 09 Diagnostics — one group: a read-only <pre> tail of the last 200 lines of ~/Library/Logs/notchtap/notchtap.log, fetched on section-open, plus a manual Refresh button (no live tail).
  • 10 History — one group: a reverse-chronological list of recorded notifications (time, origin, title, metadata chips for source/category/priority/event-type/rotation, body, an expandable "More details" native <details> for subtitle/topic/published time/ESPN summary/link-as-text), fetched on section-open, plus a two-step-confirm Clear history button. Empty-state copy differs depending on whether history recording is on.
  • 11 Queue — one group: a plain list of items currently waiting behind the visible card (title + priority chip), a manual Refresh button, a Skip current button (dismiss the visible card now, promote the next waiting item), and a Clear queue button (drops every waiting item; the visible card finishes its own turn untouched).
  • 12 About — five groups: identity (brand mark, version + bundle id), "What it is" (one paragraph), "How to use it" (a 4-item list with inline ./notchtap …/notchtap run -- … snippets and the three most-used shortcuts), "Tech stack" (chips: Rust core, Tauri v2, React + TypeScript, Motion, Vite), and "System" — a live 2-second-polled 2×3 stat grid (app memory, system memory, disk, platform/arch, bundle size, uptime).
